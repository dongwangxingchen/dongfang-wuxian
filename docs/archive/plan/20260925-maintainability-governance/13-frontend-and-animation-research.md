# 13｜前端、交互与动画研究规则

## 1. 前端不是最后才处理

前端治理与后端治理并行纳入总范围，但按专题推进：

- 设置页：信息架构、搜索、分组、开关、单选、输入、危险操作、折叠和无障碍；
- 下载页：任务状态、进度、速度、暂停/恢复/取消、批量操作、空态和失败；
- 软件库/蓝奏 WebView：加载、等待、错误、返回、下载和外跳；
- 工具箱：结果出口、传感器/媒体生命周期、长列表和图标辨识；
- Compose AI：输入、键盘、附件、返回、切页不断流和上游边界；
- 全站：Token、弹窗、通知卡片、字阶、边距、字体缩放和性能。

## 2. 选型顺序

任何新的视觉或交互改动先按以下顺序研究：

1. 当前代码和现有 Token；
2. `黑曜/06-开源参考库`、项目历史研究和已批准配方；
3. codebase-memory/Context7/官方 Android 与 Material 文档；
4. 适合的本地 Skill 和 MCP；
5. 必要时再做外部调研或参考开源仓库。

Skill/MCP 的作用是提高研究和验证质量，不等于可以无条件引入某个库或复制某段代码。宿主依赖红线、许可证、性能和维护成本必须一起评估。

## 3. 动画原则

- 先统一状态语义，再统一曲线和时长；
- 动画可打断、可取消、可恢复；
- DOWN/UP/CANCEL 的触觉和视觉反馈有明确规则；
- 不做人为三段式 bounce；
- 不给单个按钮写特殊参数来掩盖状态链问题；
- 用户看到的“快、抽帧、卡顿”必须用 setter 日志、帧间隔、gfxinfo 和主线程证据判断；
- 宿主和 Compose 动画分别使用平台合适实现，共享 Token，不强行共用实现；
- 只测手机；不恢复手表或圆屏动画路径。

## 4. 自动安装开关当前处理

暂不修改 `LumaSwitch` 的正式动画参数。先记录：

- `setChecked()` 来源、目标、同值调用；
- animator start/cancel/end；
- attach/detach 和 layout；
- ADB/Preference 回调时序；
- 同屏其他开关的对照帧间隔。

只有确认根因后，才决定修 setter 幂等、回调链、布局或性能；参数调整必须有前后数字和手机 release 验收。
