# 09｜后续任务模板

```markdown
# DFWX-XXX｜任务名称

## 状态
研究 / 待批准 / 制作 / 待用户测试 / 继续打磨 / 完成

## 目标
用用户能理解的话写要解决的问题。

## 证据
- 当前源码/配置：文件:行号
- 当前测试/构建/真机证据：命令、设备、结果
- 旧文档或历史结论：仅作线索，说明是否已复核

## 已确认与待验证
### 已确认
### 待验证
### 不做的推断

## 用户边界
- 产品行为
- 数据处理
- 成本/服务
- 手机和发布红线

## 允许修改
逐文件列出，必要时列到类/方法。

## 禁止修改
列出相邻领域、凭据、版本、vendor 或不可逆操作。

## 实施步骤
1. 先写/补最小失败测试；
2. 改最小实现；
3. 保持旧入口或适配层；
4. 运行相关验证；
5. 记录真实结果。

## 回归测试
正常、空态、失败、恢复、取消、重建、兼容和性能。

## 验收标准
可观察、可复现、可失败，不写“感觉更好”。

## 回退方案
说明可以撤回哪些文件/提交，不使用 reset/清数据等破坏性手段。

## 未完成与下一步
只记录事实，不把待用户测试写成完成。
```

## 模型交接要求

接手模型只需阅读：

1. 本任务卡；
2. `README.md`、`01-baseline-and-scope.md` 和相关架构/测试文档；
3. 项目 `AGENTS.md`；
4. 任务允许修改的文件。

不得因为“全仓优化”而扩大文件范围；发现范围扩大就停在边界处并记录。
