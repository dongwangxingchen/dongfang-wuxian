# DFW-97 设置页「反馈与建议」入口 + FlowUs 反馈页换肤

> 用户原话（2026-10-02）：
> **「设置页加一个『反馈与建议』的入口，点进去打开 flowus 那个反馈表，
> 但是它的风格和我的软件不一样，你得统一一下。」**
>
> 位置由用户指定：**「检查更新」上方**。
> 理由：反馈是"我想说点什么"（高频、主动），检查更新是"我怀疑有问题"（低频、被动），
> 主动的放上面更顺手。

## 一、换肤踩过的坑（这一节比结论重要）

### 第一版：靠类名猜选择器 —— **实测直接翻车**

```css
html, body, #root, [class*="flowus"] { background-color: #000 !important; }
body, p, span, div, label { color: #E8E6EF !important; }
```

想当然地认为"把 body 刷黑、文字刷浅就完事了"。**Playwright 真机渲染出来的结果是：
白底浅字，几乎看不见 —— 比不换肤还糟。**
因为真正承载白底的是**内层容器**，`body` 刷黑根本管不到它。

### 第二版（最终）：遍历 DOM、按计算样式做明度重映射

不猜类名，直接读每个元素**真实的** `background-color` / `color` / `border-color`：

| 读到的值 | 映射成 |
|---|---|
| 接近白的底（明度 > 0.82） | `#000`（body）/ `#14121A`（其余，保留层次） |
| 接近黑的字（明度 < 0.35） | `#E8E6EF` |
| 中等灰的字（0.35–0.62） | `#8A85A0` |
| 浅灰边框（> 0.72） | `#3A3350` |
| **饱和的亮蓝**（FlowUs 的主按钮色） | **`#7C4DFF`（品牌紫）** |

外加 `MutationObserver` 跟上动态内容（FlowUs 是 SPA，内容随时重建）。

**效果（Playwright 实测）**：换肤前统计 `dark=3 / light=277`，换肤后 `dark=277 / light=3`。

## 二、三条铁律

1. **只改颜色与可见性，绝不改布局** —— 改布局会让 FlowUs 自己的表单逻辑错位。
   （`display` 是唯一例外，用来隐藏 FlowUs 自己的顶栏/底栏/横幅。）
2. **绝不碰 `pointer-events`** —— 碰了用户就点不动表单。这是最容易"为了好看把功能弄坏"的地方。
3. **不做"猜着点"** —— 预览模式横条只在**确实找到那段文字且元素真实可见**时才点；找不到就算了。
   脚本整体包在 try 里，失败只是不换肤，页面照样能用。

## 三、预览模式自动放行

FlowUs 把分享页默认开在 **Preview mode**（一条蓝色横条写着 "Preview mode, click here to submit"），
**不点它就没有提交按钮** —— 普通用户根本不知道要点。所以注入脚本会自动点掉它。

## 四、提交后给用户自己的提示

网页通过唯一的桥 `DFWX.onSubmitted()` 通知 App（**只暴露这一个信号，没有任何读写能力**），
App 弹出自己的紫色提示条：

> **已收到你的反馈，感谢！**
> 我会尽快看，重要问题会优先处理。
> 　［返回软件］

为什么不直接留 FlowUs 的英文 toast：那是第三方站点的文案，语言、配色、措辞都和 App 不一致，
而且它不告诉用户"接下来怎么办"。

## 五、如实登记：一个没做到的地方

**自动切换到「东方无限App」表单视图 —— 没做成。**

实测诊断：FlowUs 的视图切换下拉菜单，选项坐标上压着一层全屏遮罩
（`elementFromPoint` 返回 `DIV.fixed inset-0`，父级 `z-[8848]`），
注入脚本的合成点击会被它吞掉；`el.click()` 也不触发。这是 FlowUs 自己的弹层机制，
从外部很难稳定绕过。

**影响很小**：换肤之后那个下拉菜单本身就是深色+紫的，用户点两下就切过去了；
而且默认视图（表格）里也有 FlowUs 自己的视图切换器。
与其写一段"看起来在自动切、其实时灵时不灵"的代码，不如不做、写清楚。
