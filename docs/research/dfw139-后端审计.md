## 二、逐条证据

### B1 🔴 超管登录可走明文 HTTP

**怎么验的**：

```bash
curl -s -X POST "http://39.106.33.135/pb/api/collections/_superusers/auth-with-password" \
  -H "Content-Type: application/json" \
  -d '{"identity":"nobody@example.com","password":"definitely-wrong"}'
```

**返回**：`{"data":{},"message":"Failed to authenticate.","status":400}`

**为什么这是问题**：
- 返回的是 PocketBase 的**业务错误**（`Failed to authenticate.`），不是 nginx 的 405/403
  → 说明请求**真的到达并进入了 PocketBase 的认证逻辑**
- 80 端口的站点有一条规则：非 GET/HEAD 一律 405，**但 `/pb/` 路径例外**：
  ```nginx
  if ($request_method !~ ^(GET|HEAD)$) { set $pb_write 0; }
  if ($request_uri ~ ^/pb/)            { set $pb_write 1; }
  if ($pb_write = 0)                   { return 405; }
  ```
- 结果：**超管密码可以走 `http://` 明文提交**。公共 WiFi / 运营商 / 任何中间节点都能截获
  → 截获 = 后端被完全接管（能改公告、改版本记录、改控制台状态）

**为什么 `/admin/` 没事**：`/admin/` 有显式 301 跳 HTTPS（实测确认），但 `/pb/` 没有。

**注意**：用户平时用的是 `https://39.106.33.135/admin/`（HTTPS），所以**至今没被利用**。
但这是一颗定时炸弹——只要有人（或任何工具/书签）走了 http 就会中招。

### B3 🟡 PocketBase 以 root 运行

```bash
systemctl cat dfwx-pb | grep User      # User=root
```

**为什么这是问题**：PocketBase 是 Go 写的单文件服务，直接暴露在公网（经 nginx）。
一旦它有漏洞被利用，攻击者**直接拿到 root**，而不是一个受限用户。

**对照**：`dfwx-upload` 是 `User=www-data` ✅ —— 说明这台机器上已有正确做法可参照。

---

### B4 🟡 无 swap + dfwx-pb 无内存上限

```bash
free -m        # 总 1613MB / 可用 1072MB / Swap 0
systemctl cat dfwx-pb | grep MemoryMax   # 无
```

**为什么这是问题**：
- 机器只有 1.6GB 内存且**没有 swap**
- `dfwx-pb` 实测 RSS ~100MB，但没有内存上限
- 一旦内存吃满，**Linux 的 OOM killer 会杀进程**——可能杀掉 PocketBase 或 nginx

**修复方向**（待定）：给 dfwx-pb 加 `MemoryMax`，或加一个小 swap 文件做缓冲。

### B6 🟡 6 天短证书 + 续期要停 nginx

**怎么验的**：

```bash
openssl x509 -in /etc/letsencrypt/live/dsh-ip/fullchain.pem -noout -dates
#   notBefore=Oct  3 04:41:07 2026 GMT
#   notAfter =Oct  9 20:41:06 2026 GMT   ← 只有 6 天
#   SAN: IP Address:39.106.33.135        ← 是 IP 证书，不是域名证书
cat /etc/letsencrypt/renewal/dsh-ip.conf | grep preferred_profile
#   preferred_profile = shortlived        ← Let's Encrypt 的 6 天短证书档
```

**自动续期本身是好的** ✅：
- pre 钩子 `/etc/letsencrypt/renewal-hooks/pre/stop-nginx.sh`
- post 钩子 `/etc/letsencrypt/renewal-hooks/post/start-nginx.sh`
- `certbot renew --dry-run` **实测成功**
- `certbot.service` 今天 02:05 跑过，`status=0/SUCCESS`

**但有两个长期风险**：
1. **每 3 天左右续期一次**（6 天证书的续期窗口很窄）。每次都要 stop nginx → 续期 → start nginx
   → **网站每 3 天短暂中断一次**
2. **单点失败**：任何一次续期失败（Let's Encrypt 抖动、DNS 解析、端口占用），
   **6 天内证书就过期，HTTPS 全挂**。而域名证书是 90 天，有 3 个月的缓冲

**这是「7 天后就过期」的同类问题，用户特别点名要处理。**

**根因**：目前用的是 **IP 证书**。Let's Encrypt 的 IP 证书只发 6 天。
如果换成域名证书（90 天），这个问题就从根上消失——但用户此前明确说过域名「等申请后备案」，
而现在卡 DFW-108 写着「决定：不备案，官网放境外」。
