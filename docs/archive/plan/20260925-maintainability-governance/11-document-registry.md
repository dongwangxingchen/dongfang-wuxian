# 11｜文档注册表与冲突处理

## 2. 冲突处理

每次发现冲突，新增一条纠偏记录：

```text
原判断：
证据来源：
当前复核：
新结论：
影响任务：
```

不直接删除旧文档中的历史语句，因为它们可能解释过去为什么做出某个决定；但要在当前入口明确哪些已失效。

## 3. 已知冲突

- 长期计划 README 的 HEAD/工作树快照落后于当前 `30af1f0`；
- `SECURITY.md` 的版本、资产名、内置 AI 和 HTTP 描述落后于当前用户决定；
- 设计文档含旧 Wear/弹簧语境，当前只测手机，触摸动画以最新项目规范、当前代码和实测为准；
- 历史计划曾把内置 AI、HTTP 或某些动画视为已批准，但用户当前已决定移除内置 AI、外部 HTTPS-only，旧决定不再自动生效；
- 旧专题的“已完成”只表示当时记录，不表示 v1.22.4 当前验证完成。

## 4. 文档健康检查

每个阶段结束时检查：

- 所有路径仍存在；
- 行号或符号仍可定位；
- 旧快照是否标明日期；
- 用户决定是否重复且一致；
- 没有凭据、真实 Key、Cookie、签名密码和完整敏感 URL；
- 任务状态是否把“待用户测试”误写为“完成”。
