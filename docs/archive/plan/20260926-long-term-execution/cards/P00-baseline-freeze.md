# P00｜已有工作保护与开工基线

**性质**：准备专题，不改业务源码，不自动提交、不清理工作区。

## 要解决的问题
当前工作区混有导航/权限、解析、更新、工具页、测试和文档改动。后续每个专题必须知道哪些内容是已有成果、哪些文件会重叠、失败时怎样只回退本专题。

## 推荐方向
只做轻量、可复查的基线整理：按功能归属查看状态和 diff，确认当前可重跑的证据，记录不确定归属；不把 P00 变成“先把所有东西提交干净”。用户是否提交、如何分批提交，另行决定。

## 研究重点
- `git status --short`、`git diff --stat` 和与当前专题相关的 diff；不需要全文打印无关大文件。
- 区分导航/AI 引导、T6 解析、T14 更新、T12 验证工具、测试和文档；标出同一文件被多个专题使用的地方。
- 只检查 `local.properties` 是否被忽略，不读取或打印任何值。
- 对已有 T6/T14 证据按当前工作树重新核对；测试是否需要重跑由实际专题风险决定。

## 用户验收
- 能看懂当前混合改动和后续边界；没有原有改动被覆盖、清理或伪装成新成果。
- 凭据没有出现在命令输出、日志或计划中。
- 能为下一项专题指出最小可回退范围。

## 结束条件
P00 完成后停下，把基线摘要交用户确认；不自动提交，不自动开始 T1 或其他专题。若发现改动归属无法安全分开，保留现状并报告，不用回退命令解决。

## 红线
禁止 `git reset --hard`、`git checkout --`、卸载、清数据、`pm clear`、`adb shell rm`、删除源和覆盖<本地加密备份>/<本地备份>。任何不可逆动作需用户另行明确批准。
