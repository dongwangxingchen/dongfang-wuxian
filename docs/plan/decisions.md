# 东方无限：已确认决定

> 只记录已经拍板的长期规则。临时想法和待选方案放到对应任务卡，不写进这里。
> 更新日期：2026-09-28 晚

## 产品方向

1. 不是只做 UI 外表；宿主、vendor、后端链路、数据、线程、发布和测试一起治理。
2. 当前旧 AI 对话接入整体移除，重新核对并接入 RikkaHub 稳定版本，再做东方无限适配；不是删除 AI 功能。
3. 当前内置 AI 模型、内置渠道、默认 URL 和默认 Key 直接移除；不做“保留渠道让用户填写 Key”的过渡。
4. 赞助页、关于页、致谢页、设置页、下载页、软件库入口和 AI 页都要按统一产品标准分别重做和验收。
5. 旧计划保留为历史证据；新总计划作为唯一实施入口，旧文档归档后不再直接指挥源码。
6. 文件名使用稳定、清楚的普通名称，不添加“最新版、修改版、终版、治理版”等无意义后缀。

## 安全和数据

7. 外部 Intent 下载保留，但外部 APK 安装前必须用户确认；不能直接自动安装或 Shizuku/ADB 静默安装。
8. 蓝奏云、外部下载、官方更新和未知历史记录分型处理；不把外部 URL 写入蓝奏云直链缓存。
9. 普通外部 AI/API 只允许 HTTPS；未来 loopback HTTP 必须单独研究、测试和记录。
10. 用户自建、导入或已修改 Provider 不得因 AI 重做被误删；无法证明来源时宁可保留。
11. `local.properties`、签名密码、Key、Token、Cookie 不得外传、入脚本或日志。
12. release 缺少签名配置时必须失败，禁止硬编码 fallback。

## 测试和发布

13. 只测手机，手表测试永久停止；Robolectric/JVM 作为快速回归主力。
14. 手机不可逆操作（卸载、清数据、`pm clear`、删除文件）必须先请示。
15. 发布标题只用纯 `vX.Y.Z`，APK 资产只用 `dongfang-wuxian-vX.Y.Z.apk`；测试期递增，正式发布再重置 1.0.0。
16. APK 发布履行 AGPL-3.0 同协议源码义务，保留 RikkaHub 上游署名。
17. 宿主不随意引入第三方依赖；vendor 修改必须记录 `rikkahub/PATCHES.md`。
18. 动画先取证，确认 setter、cancel/restart、attach、layout、主线程和帧间隔根因后再改，不靠单控件参数掩盖状态问题。

## 交接方式

19. 后续 AI 一次只接一个任务卡；先读总入口、当前状态、决策、风险和任务卡，再看代码。
20. 没有测试和证据不能标记完成；没有回退点不做跨领域修改。
21. 不自动提交、push、发布或操作用户手机。

## 调研与设计纪律

22. 调研三层查（2026-09-25 固化）：先查本地黑曜参考库 → 再用结构化工具（codebase-memory、context7、gh）→ 最后才外网搜索或子代理外包；不直接跳到外网。
23. T5-S 设计稿 v1 是审美锚点：v2-v5 已全部否决（含照搬外部模板构图）；配色永远锁软件紫暗系，外部参考只借构图不借配色；优化一次只动一处，渐进推进。
24. 文案品味红线：副题只定性不教操作；"切换后会跟着变"式功能复述文案被判掉价，禁止再写。
25. 用户正在使用手机时禁止坐标点击自动化；提问一律正文文字列选项，不用按钮组件；每张任务卡动手前先用大白话向用户汇报并等同意（详见 `docs/tasks/README.md` 铁规矩节）。
