## 产品方向

1. 不是只做 UI 外表；宿主、vendor、后端链路、数据、线程、发布和测试一起治理。
2. 当前旧 AI 对话接入整体移除，重新核对并接入 RikkaHub 稳定版本，再做东方无限适配；不是删除 AI 功能。
3. 当前内置 AI 模型、内置渠道、默认 URL 和默认 Key 直接移除；不做“保留渠道让用户填写 Key”的过渡。
4. 赞助页、关于页、致谢页、设置页、下载页、软件库入口和 AI 页都要按统一产品标准分别重做和验收。
5. 旧计划保留为历史证据；新总计划作为唯一实施入口，旧文档归档后不再直接指挥源码。
6. 文件名使用稳定、清楚的普通名称，不添加“最新版、修改版、终版、治理版”等无意义后缀。

## 安全和数据

7. 外部 Intent 下载保留，但外部 APK 安装前必须用户确认；不能直接自动安装或 Shizuku/ADB 静默安装。
8. 蓝奏云、外部下载、官方更新和未知历史记录分型处理；不把外部 URL 写入蓝奏云直链缓存。
9. 普通外部 AI/API 只允许 HTTPS；未来 loopback HTTP 必须单独研究、测试和记录。
10. 用户自建、导入或已修改 Provider 不得因 AI 重做被误删；无法证明来源时宁可保留。
11. `local.properties`、签名密码、Key、Token、Cookie 不得外传、入脚本或日志。
12. release 缺少签名配置时必须失败，禁止硬编码 fallback。

## 测试和发布

13. 只测手机，手表测试永久停止；Robolectric/JVM 作为快速回归主力。
14. 手机不可逆操作（卸载、清数据、`pm clear`、删除文件）必须先请示。
15. 发布标题只用纯 `vX.Y.Z`，APK 资产只用 `dongfang-wuxian-vX.Y.Z.apk`；测试期递增，正式发布再重置 1.0.0。
16. APK 发布履行 AGPL-3.0 同协议源码义务，保留 RikkaHub 上游署名。
17. 宿主不随意引入第三方依赖；vendor 修改必须记录 `rikkahub/PATCHES.md`。
18. 动画先取证，确认 setter、cancel/restart、attach、layout、主线程和帧间隔根因后再改，不靠单控件参数掩盖状态问题。

## 交接方式

20. 没有测试和证据不能标记完成；没有回退点不做跨领域修改。

## 调研与设计纪律

22. 调研三层查（2026-09-25 固化）：先查本地黑曜参考库 → 再用结构化工具（codebase-memory、context7、gh）→ 最后才外网搜索或子代理外包；不直接跳到外网。

24. 文案品味红线：副题只定性不教操作；"切换后会跟着变"式功能复述文案被判掉价，禁止再写。

## 2026-09-30 远程控制与更新体系（用户逐条拍板）

31. **自建后台采用 PocketBase**（单文件 Go + SQLite + 自带管理后台，MIT，实测 61,214★、2026-09-28 仍活跃）。
    理由：服务器**无 Docker、仅 1.6G 内存**，Directus/Strapi 官方要求 ≥2GB 会挤爆现有服务；
    PocketBase 单文件即跑、内存占用极小。**装完不追新版本**（1.0 前不保证向后兼容）。
32. **更新/维护模式方向不引任何 Android 库**：实测候选全部不可用
    （AppUpdater 两年停更、AutoUpdateProject **无许可证**、其余 ≤4★）；
    现有 `UpdateClient` 已强于它们。App 端 UI 用项目自身 View 体系 + 既有 M3E 动效 token。
33. **网络走 HTTP，不走 HTTPS**（用户选 B）：安全性由 **sha256 + 包名 + 签名证书三重校验**保证
    （系统级签名比对，篡改包装不上）；**用户零维护**，不用管证书。
    后续 HTTPS 升级见 #38。
34. **维护/停更页：无按钮、点空白不关、返回键无效**（用户原话"纯粹的通知"）。
    文字全部由后台字段驱动，**代码不写死任何一个字**。
    **维护时间用单独 UI 区块**展示（留空不显示，"永久"也可填）。
    **必须留隐藏后门**（连点版本号 7 次跳过）——否则误开后用户与自己都被锁死。
35. **强制更新页文字可自定义**（如"已停更，不再维护"），按钮可有可无，全由后台填。
36. **更新弹窗四按钮**：立即更新（主）/ 其他下载方式（次）/ 取消更新 / 不再显示（弱化文本钮）。
    "不再显示"只针对**该具体版本**，换版本照弹。强制模式无取消与不再显示。
37. **刷新策略**：**每次启动自动拉取**（用户要求），但**无 loading / 无 Toast / 失败静默**——
    "不要有明显痕迹"；红点出现与消失走 M3E effects 弹簧（500/1.0），**禁止瞬切**。
38. **【待做·发布后】HTTPS 升级项已写进计划表**（`docs/plan/remote-control-plan.md` §五）。
    用户 2026-09-30 明确要求"写进计划表，别忘了"。
    做法：:443 加子路径反代 PocketBase、复用现成 Let's Encrypt 证书；
    **必须**先备份 → `nginx -t` → `systemctl reload`（:443 现为 DSH 的 sshd 隧道，改错会影响用户当前会话）。
39. **拉不到服务器配置一律 fail-open**（按正常处理）：绝不因服务器故障把全部用户锁在门外。
    ——这是与"高权限控制"的必要对冲。
40. **更新记录（更新历史）对接后台**（用户 2026-09-30 追加）：后台 `changelog` 集合可叠加多条，
    **用户与 AI 皆可修改**；App 内提供**更新后弹窗（可下滑浏览全部历史）** +
    常驻"更新记录"入口。展示按日期倒序，含版本号与改动条目。
41. **后台改为浏览器直连（用户选 A）**：入口 `https://39.106.33.135/pb/_/`。
    实施中**发现必须走 HTTPS**——现代浏览器会把 http 自动升级为 https，
    走 80 会被升级后撞上 443 的 DSH（实测 `ERR_HTTP_RESPONSE_CODE_FAILURE`），
    故把原定"发布后"的 443 改造提前执行。做法：443 内**只新增** `location /pb/`，
    DSH 的 `location /` 一行未动；改前备份 → `nginx -t` → `reload`。
    实测 DSH 与后台同时 200，正确密码可登录。**登录端点加 nginx 限流（6 次/分钟，实测第 4 次 429）**，
    因为 PocketBase 自身对错误密码不限流（实测连打 8 次全 400）。
