# 远程控制与更新体系 · 实施方案（2026-09-30 立项）

> 用户 2026-09-30 逐条拍板后立项。本文件是**唯一实施方案**，实施中出现偏差先改这里。
> 相关决策已同步 `docs/plan/decisions.md` #31–#38。

## 一、用户要的是什么（原话归纳）

1. **要有自己的后台**，能改公告、换版本、传 APK，**不依赖 AI 也能操作**；
   而且"**权限也得高**"——即停用/维护这类控制权也要在他手上。
2. **后台必须分好类、非常简单易懂**，不留一堆乱七八糟的字段让他瞎改。
3. **公告是可叠加的发布式**：发多条都保留；想弹就弹、不想弹就静默发；用户随时能看。
4. **维护页**：只显示公告文字，**没有按钮、点空白不关闭、返回键无效**——纯粹的通知。
   文字全由他填（维护原因 / 永久停更都行）。**维护时间用单独的 UI 展示**。
5. **强制更新页**：文字可自定义（例如"已停更，不再维护"），按钮可有。
6. **更新弹窗四个按钮**：不再显示 / 取消更新 / 其他更新方式 / 立即更新。
   （布局由实施者定，见 §四）
7. **每次打开软件自动刷新**，但**不要有明显痕迹**；红点出现要有**丝滑专属动画**。
8. **更新分级可叠加**：软更新（可关、可"不再显示"）/ 强制更新 / 维护停用。
9. **更新记录（更新历史）也对接到后台**（2026-09-30 追加）：
   后台可维护**历次更新日志**，**用户与 AI 都能改**；
   **用户能看见更新历史**——更新完成后弹窗可**下滑浏览**，按日期看每一条改了什么。

## 三、服务器端（实测数据支撑）

### 现状（已核对）
- `39.106.33.135`：阿里云轻量 北京，`ecs.e-c1m1.large`，2核2G，<日期> 到期
- **出网带宽 204800 Kbit/s ≈ 25 MB/s**（元数据实测）；**实测下载 24–25 MB/s**，
  5 并发每人仍有 3–15 MB/s → **36MB 包 1.5 秒下完，带宽完全够**
- 内存可用 1.1G；磁盘剩 35G
- **只在 80 / 443 对外**（已探 14 个端口，8443/8080/2053 等全不通）
- :80 = 现有 dfwx 站点（`/health`、`/api/*.json`、`/apk/`）；:443 = **sshd 隧道（DSH 专用）**
- **服务器可直连 GitHub（实测 HTTP 200）** → 可自动同步 APK，无需人工上传
- certbot.timer 每日两次 + pre/post 钩子，`renew --dry-run` 通过

### 部署内容
1. **PocketBase**（单文件 ~12MB，Go，**无需 Docker**）装到 `/opt/dfwx-pb/`
2. **只监听 127.0.0.1:8090**（不直接暴露）
3. **三个集合（严格分类，字段精挑，不给用户乱改空间）**：
   - **`notice`（公告）** — 可叠加多条
     `title` / `body` / `level`（普通·重要·紧急）/ `pinned` / `popup`（是否启动弹窗）/ `enabled`
   - **`release`（版本）** — 一行即当前版本
     `versionName` / `versionCode` / `apkUrl` / `sha256` / `size` / `changelog` / `updateMode`
     （`soft` 软更新 / `force` 强制更新 / `off` 不提示）
   - **`changelog`（更新记录 / 更新历史）** — **可叠加多条**，一条一个版本
     `versionName` / `date` / `highlights`（本次改了什么，多行）/ `enabled`
     → 既给更新弹窗的"更新内容"用，也拼成 App 内的**更新历史**页
   - **`control`（总控）** — **只有一行**，避免误改
     `maintenanceOn` / `maintenanceTitle` / `maintenanceBody` / `maintenanceUntil`
     （填"永久"或时间文本，留空不显示）/ `blocked`
4. **API 规则**：以上三个集合**公开只读**（App 能读），**仅超管可写**（只有你能改）
5. **APK 自动同步脚本**（systemd timer，每天一次）：
   从 GitHub Releases 拉最新 → 下载到 `/var/www/dfwx/apk/` → 算 sha256 → 更新 `release` 集合
   → **发版时你只需传 GitHub，服务器自动跟上**
6. **nginx 反代**：`:80` 上加 `/dfwx-api/` → `127.0.0.1:8090`
   （后台管理页走 ssh 隧道访问，**不对公网暴露登录入口**）

### 后台访问方式（你能操作）
浏览器打开后台 → 只用 ssh 隧道映射到本机，安全且不暴露：
`ssh -L 8090:127.0.0.1:8090 dfwx` → 然后浏览器开 `http://127.0.0.1:8090/_/`
（我会写一个一键脚本，双击即可）

## 四、App 端

### 4.1 更新弹窗（四按钮布局，实施者定）
Material 3 建议对话框最多 3 个动作，四个按钮的**最优排布**：

```
┌─────────────────────────────────┐
│  发现新版本  1.22.20              │  ← 标题
│  ─────────────────────────────  │
│  更新内容：…                      │  ← changelog（可滚动，最多 N 行）
│  ─────────────────────────────  │
│  📦 36.6 MB · 已校验签名           │  ← 元信息
│                                  │
│  ┌───────────────────────────┐  │
│  │        立即更新            │  │  ← 主按钮（filled，全宽，最高权重）
│  └───────────────────────────┘  │
│  ┌───────────────────────────┐  │
│  │      其他下载方式          │  │  ← 次按钮（outlined，全宽）
│  └───────────────────────────┘  │
│      取消更新    ·    不再显示    │  ← 两个文本按钮，弱化，同一行底部
└─────────────────────────────────┘
```

- **「不再显示」**= 记住**这个具体版本**，该版本不再弹（换新版本照弹）
- **「其他下载方式」**→ 第二层：GitHub 页（标注"需科学上网"）/ FlowUs 页（跳浏览器）
- **强制更新模式**：只有「立即更新」+「其他下载方式」，**无取消、无不再显示**
- `updateMode=off`：完全不弹

### 4.2 维护 / 停更页（无按钮）
- **全屏拦截**：无按钮、点空白不关闭、**返回键无效**（用 `OnBackInvokedCallback` 吃掉）
- 只有公告文字（`maintenanceTitle` + `maintenanceBody`，全由后台填）
- **维护时间单独一个 UI 区块**（`maintenanceUntil`）：留空不显示；填"永久"就显示"永久"
- **隐藏后门**：连点版本号 7 次可跳过 → **防止误开后用户和你自己都被锁在外面**
- **fail-open**：服务器连不上按"正常"处理，绝不因服务器故障锁死用户

### 4.2b 更新记录 / 更新历史（用户 2026-09-30 追加）
- 数据源：后台 `changelog` 集合（可叠加），**后台与 AI 两侧都能改**
- **更新完成后弹一次"更新记录"弹窗**，**可下滑浏览**全部历史：
  按日期倒序，每条显示 `日期` + `版本号` + 改动条目
- 另有常驻入口（设置页"更新记录"），**随时可看**，不必等更新
- 弹窗内滚动用项目既有滚动容器，**不做花哨动画**（避免 v1.22.8 自研动画事故重演）

### 4.3 公告中心 + 红点（丝滑动画）
- 入口：**设置页"公告"** + **首页右上角铃铛**（有未读才出现）
- **未读红点**：出现/消失走 M3E `effects` 弹簧（500/1.0），**不瞬切**
- 红点带**内容驱动动画**：数字变化时缩放+换字，非整块重绘
- 公告列表：可叠加、置顶、等级色、时间、已读/未读
- `popup=true` 的公告启动时弹一次

### 4.4 静默刷新（"不要有明显痕迹"）
- **每次启动**拉一次（用户要求），但：
  - **无 loading 转圈、无 Toast、无闪屏**——拿到结果才动 UI
  - 失败静默（不弹任何提示）
  - 红点变化走动画，不是突然出现
- 后台运行时每 6 小时拉一次；手动刷新入口保留

### 4.5 网络层
- `UpdateClient` 扩展：支持自有服务器（**HTTP + IP**）
- `network_security_config.xml` 白名单加 `39.106.33.135`
- **安全靠三重校验**：sha256 + 包名 + **签名证书必须与已安装一致**（系统级校验，篡改包装不上）

## 五、后续升级项（用户点名必须写进计划表）

> **【DFW-19-HTTPS】发布稳定后再做，用户 2026-09-30 同意（原话"可以，不过你得写进计划表里面，别忘了"）**

- **现状**：走 HTTP（`http://39.106.33.135`），安全性由 App 端三重校验保证，**用户零维护**
- **升级内容**：在 :443 的 nginx server 块内**加子路径**（如 `location /dfwx/`）反代到
  PocketBase，**复用现成 Let's Encrypt 证书**（实测 `Verify return code: 0`，Android 默认信任）
- **风险与规避**：:443 现由 DSH 使用（sshd 隧道），**必须**先备份配置 → `nginx -t` → `systemctl reload`
  （平滑重载，配置有错自动保持旧配置）；`ssh dfwx` 是独立通道，可救回
- **不做也不影响功能**：HTTPS 是"体面"，不是"安全必需"
- **证书说明**：短效证书 7 天滚一次，certbot.timer 自动续期（dry-run 已验证）；若挂掉我会提前告知

## 六、风险与取舍（如实记录）

| 风险 | 处置 |
|---|---|
| 维护模式误开→用户和你都进不去 | **隐藏后门**（连点版本号 7 次）+ 后台开关状态醒目提示 |
| 服务器故障导致用户全部打不开 | **fail-open**：拉不到配置=按正常处理 |
| PocketBase 1.0 前不保证兼容 | **装完不追新版本**（"装完就忘"型），需要升级时由 AI 做迁移 |
| 阿里云月流量包超额计费 | 用户只在更新时下载（非每次启动），按引流规模风险极低；后续可加流量监控 |
| 纯 IP + HTTP 不够体面 | 见 §五，发布后升级 HTTPS |

## 九、本轮实测抓出并修掉的两个真实缺陷

两个都是**"请求返回 200 成功，但结果看不到"**的类型，极易被误判成"后端没好"：

### 1. PocketBase 0.40 的 `created` 不是可排序字段
`sort=-created` 与 `sort=created` 都返回 **400**（只有 `sort=-id` 是 200）。
表现为：**单条写入 200 成功，但列表查询静默失败** → "提示发布成功，列表却看不到"。
**影响两处，均已修**：控制台 `index.html`、App 端 `RemoteConfigClient.items()`。

### 2. 写操作后只 `load()` 不重绘
`load()` 只把数据放进 cache，**界面不会自动变**。
表现为"提示已保存，但列表还是旧的"。已抽出 `refresh() = load() + renderPane()`，
七处写操作全部改用它（实测：发布后 1→2 条即时可见，删除后即时消失）。
